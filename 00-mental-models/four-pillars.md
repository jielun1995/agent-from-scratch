# 心智模型 2：Agent 工程的四大支柱

学完四节课后，我提炼出的核心判断：**真实生产级 Agent 工程，就是把这四件事都做对。**

## 四元组

> **循环（Loop）+ 规划（Plan）+ 评估（Eval）+ 上下文（Context）**

| 支柱 | 解决什么问题 | 对应课程 |
|------|-------------|---------|
| **循环 (Loop)** | Agent 怎么自主运行？ | [01](../01-react-loop/) |
| **规划 (Plan)** | 复杂任务怎么分解？ | [02](../02-plan-execute/) |
| **评估 (Eval)** | 怎么知道它工作得好？ | [03](../03-evaluation/) |
| **上下文 (Context)** | 怎么让它跑得又好又便宜？ | [04](../04-context-engineering/) |

## 为什么是这四个

行业里所有花哨概念都能归约到这四元组：

- **多 Agent 协作** = 多个循环 + 跨循环的规划与上下文传递
- **MCP / 工具生态** = 给循环更好的工具，给上下文更结构化的注入
- **Agent Memory** = 跨循环的上下文持久化
- **Workflow vs Agent** = 规划的灵活度光谱
- **AutoGPT / Devin 等长程 Agent** = 极致的循环 + 规划 + 上下文管理

## 一个判断力练习

下次看到一个"新的 Agent 创新"，问自己三个问题：

1. 它在四元组的哪一支柱做了改进？
2. 这个改进的代价是什么（其他三个支柱变差了吗）？
3. 如果是我，会怎么实现类似效果？

能回答这三个问题，你就摆脱了"被新概念牵着走"的状态。
